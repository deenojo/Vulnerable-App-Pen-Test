# F01: SQL Injection

| | |
| --- | --- |
| **Severity** | Critical |
| **OWASP** | A03:2021 – Injection |
| **CWE** | CWE-89 |

## Finding
Invoice search concatenated the `q` parameter into the SQL string, so input like `' OR '1'='1` changed the query and `x'); DROP TABLE invoices;--` could destroy data.

## Fix
The query binds the term as a parameter (`... customer LIKE ?`, `(f"%{term}%",)`), so the database treats it as a literal value, never as SQL.

**Code:** `app/ledgerly.py` → `search_invoices`

## Retest
`tests/test_f01_injection.py` — tautology returns `[]`, the table survives a DROP attempt, real searches still work.

**Detection rule:** `formatted-sql-string` in [`semgrep/rules.yaml`](../semgrep/rules.yaml) fails CI if this pattern reappears.
