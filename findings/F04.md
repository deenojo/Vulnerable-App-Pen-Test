# F04: Server-Side Request Forgery

| | |
| --- | --- |
| **Severity** | High |
| **OWASP** | A10:2021 – SSRF |
| **CWE** | CWE-918 |

## Finding
The logo endpoint fetched any URL the user supplied, so `https://169.254.169.254/latest/meta-data/` would make the server read cloud credentials and `https://localhost/...` would reach internal services.

## Fix
`validate_outbound_url` requires HTTPS, an allowlisted host, and that every resolved address is public — loopback, link-local (incl. 169.254.169.254), private and reserved ranges are rejected before any request.

**Code:** `app/security.py` → `validate_outbound_url`; `app/ledgerly.py` → `set_logo`

## Retest
`tests/test_f04_ssrf.py` — metadata, loopback, non-HTTPS and off-allowlist URLs all raise; the endpoint returns 400.

**Detection rule:** `ssrf-request-from-user-input` in [`semgrep/rules.yaml`](../semgrep/rules.yaml) fails CI if this pattern reappears.
